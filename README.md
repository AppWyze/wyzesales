# WyzeSales

Flutter + Supabase front end for Water Components SA's sales, quote, and budget
analysis — replaces the old QlikView/Xojo desktop app. Reads the tables and
views created by `docs/schema/001`–`005` and the rows written by the rewritten
`WyzeSalesExtract`. This is a separate project from SeaWyze (own app, own
Supabase project) — it copies SeaWyze's navy/teal theme values so the two
apps look related, rather than sharing a package between them.

## Important — read this before you build

This project was written in a sandbox with **no access to pub.dev or the
Flutter/Dart SDK download servers**, so nothing here has been through a real
`flutter pub get`, `flutter analyze`, or `flutter run`. What verification
*was* possible is described in `docs/WyzeSales_Flutter_App_DesignNotes.md`
("How this was verified") — it's meaningfully weaker than the check the
rewritten `WyzeSalesExtract` got, and that document says exactly why. Budget
time for a real first build to surface issues a compiler would normally have
caught before you ever saw this code — that's expected, not a sign
something went obviously wrong.

## First-time setup

1. **Install Flutter** if you haven't already (`flutter --version` to check).
   This project targets Dart 3.3+/a current Flutter stable release.

2. **Add the platform folders.** This zip only contains `lib/`, `pubspec.yaml`,
   and a few config files — no `android/`, `ios/`, `web/`, etc. Those are
   normally generated by `flutter create`, which this sandbox couldn't run.
   From inside this project folder, run:

   ```
   flutter create --org com.wyzelink --platforms=web,windows,android,ios .
   ```

   Run this **after** these files are already in place, not before — pointed
   at a folder that already has a `pubspec.yaml`, `flutter create` fills in
   only the missing platform folders and leaves `pubspec.yaml`/`lib/` alone.
   Drop any platform you don't need from that comma list (e.g. just `web` to
   start).

3. **Get packages:**

   ```
   flutter pub get
   ```

   This is the real first check the sandbox couldn't run — expect this step
   (or the first `flutter analyze`) to surface anything wrong with a package
   version or import.

4. **Configure which Supabase project this points at.** The Supabase URL and
   anon key are never hardcoded — they're passed in at run/build time so the
   same code can point at Staging or Production:

   ```
   flutter run -d chrome \
     --dart-define=SUPABASE_URL=https://<your-staging-project>.supabase.co \
     --dart-define=SUPABASE_ANON_KEY=<staging-anon-key>
   ```

   For a VS Code launch config, add these under `"args"` as
   `"--dart-define=SUPABASE_URL=...", "--dart-define=SUPABASE_ANON_KEY=..."`
   in `.vscode/launch.json` (not committed — keep Staging/Production keys out
   of source control the same way the anon key itself is safe to embed in a
   built app, but worth keeping Staging vs. Production launch configs
   separate so you don't fat-finger which one you're pointed at).

5. **Create at least one login.** There's no self-service sign-up screen —
   Supabase Auth users are created from the Supabase dashboard (Authentication
   → Users → Add user), and a matching row in `profiles` is needed for them
   to see anything (schema/001 Section 6) — without a `profiles` row, RLS
   correctly shows them nothing, which is by design, but is worth knowing
   before your first login looks like a blank app.

## Running against Staging first

Point step 4 at your Staging Supabase project (with schema/001–005 applied
and some real extracted data in it) before ever pointing this at Production —
same recommendation as the `WyzeSalesExtract` README.

## What's built and what's a placeholder

All 8 screen types from `Wyzesales_Screens_and_Recommendations.md` exist and
read real data: Dashboard, Sales Analysis (Graph + Table tabs), YTD
Comparative, Quote Analysis, Sales Order Analysis, and the 3 dimension
templates (Sales by / Budgets / Performance) covering all 5 dimensions each.
Auth (sign in, sign out, password reset email) and role-based visibility
(via RLS + `profiles.level`) work.

Deliberately left as placeholders, not silently skipped — see
`docs/WyzeSales_Flutter_App_DesignNotes.md` for the reasoning on each:

- **PDF/CSV export** buttons are present but show "not yet implemented."
- **Charts are tables, not line/bar charts.** No charting package was added
  since it couldn't be verified here — the Dashboard's "Top 5" cards use a
  simple hand-drawn bar, and Sales Analysis' Graph tab is a table.
- **Sales Analysis' Graph tab and YTD Comparative show whole-company totals**,
  not yet filtered by the screen's own Category/Item/Rep/Branch/Customer
  filters — see the design notes for why.
- **Password reset** sends the email but there's no in-app "set your new
  password" screen yet to complete the flow.

## Project layout

```
lib/
  core/            theme, router, Supabase bootstrap, fiscal-year helpers, providers
  data/
    models/        one class per table/view this app reads
    repositories/   all Supabase queries live here, nowhere else
  shared/widgets/   filter bar, data table, bar chart, app shell/nav — reused across screens
  features/         one folder per screen, screens only build UI from a repository call
```
